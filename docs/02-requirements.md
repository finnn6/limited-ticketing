# 요구사항
## 기능 요구사항
- 관리자가 이벤트(총 수량, 오픈 시각, 마감 시각, 1인당 발급 한도)를 등록한다
- 사용자는 오픈 시각 이후에만 발급을 신청할 수 있다
- 한 사용자는 같은 이벤트에서 한도 이상 발급받을 수 없다 (중복 방지)
- 잔여 수량은 화면에 실시간으로 갱신된다
- 수량이 소진되면 이후 요청은 "마감" 응답을 받는다
- 사용자는 자신의 발급 내역을 조회할 수 있다

## 비기능 요구사항
- **정합성**: 재고 100개에 동시 요청, 1000건이 들어오면 발급은 정확히 100건, 초과-중복 발급은 0건
- **성능**: 동시 N명(예: 1000명) 요청 시 p95 응답시간 X ms 이내
- **멱등성**: 같은 요청이 재시도돼도 중복 발급되지 않는다 (네트워크 재전송, 더블클릭 대비)
- **장애 대응**: Redis나 서버가 중간에 죽어도 재고와 발급 내역이 어긋나지 않는다 (복구 방법 정의)

## 개발 핵심 포인트
완성된 서비스가 아니라 동시성 문제를 재현하고 단계적으로 해결하는 과정을 구현해보기.
1. 락 없이 구현해서 초과 발급 문제를 부하 테스트로 직접 재현
2. DB 비관적 락 / 낙관적 락
3. Redis 원자 연산(DECR, Lua 스크립트)
4. 분산 락(Redisson)
5. 큐 기반 비동기 처리
